# 최종 시스템 설명

## 1. 문제 정의

Vpick은 롱폼을 장면 단위로 분석해 시작·종료 시각, 장면 설명, 대사와 인물
정보를 제공하고 하이라이트 후보를 생성한다. 그러나 프롬프트나 모델을
변경했을 때 선택 품질이 실제로 좋아졌는지 판단할 고정 평가체계가 없었다.

본 프로젝트의 목표는 다음 두 가지다.

1. 새 숏폼 후보의 품질과 성공 가능성을 설명 가능한 기준으로 채점한다.
2. 구축한 평가 기준을 Vpick scene data 기반 후보 재선별에 적용한다.

## 2. 핵심 설계 결정

### 정답을 하나로 섞지 않는다

평가체계의 정답과 선택 개선의 정답은 서로 다르다.

- **성과 정합성**: Judge 점수 순위와 실제 조회 성과 순위의 일치
- **구간 정합성**: 선택 후보와 공개 숏폼 원본 구간의 시간 겹침

공개 숏폼은 실제 편집자가 선택했고 성과가 확인된 구간이지만, 구간
정합성 지표가 직접 측정하는 것은 조회수가 아니라 시간 구간 일치다.

### 콘텐츠와 배포 조건을 분리한다

LLM Judge는 채널명과 조회수를 보지 않고 콘텐츠·패키징만 평가한다.
채널의 과거 도달 규모와 게시 경과일은 채점 후 성과 보정 단계에서만 결합한다.

따라서 시스템은 두 출력을 제공한다.

- `editorial_success_score`: 채널 조건을 보지 않은 콘텐츠·패키징 점수
- `expected_reach_score`: 채널 기준선과 게시 조건을 반영한 상대 도달 예상값

### Pointwise와 Listwise의 역할을 분리한다

- **Pointwise Judge**: 신규 후보 하나를 독립적으로 평가할 수 있는 운영 평가자
- **Pairwise**: A/B 제시 순서 편향과 상대 판단을 확인하는 진단
- **Listwise Judge**: 한 롱폼의 후보군 안에서 완결된 보강 후보를 찾는 선택기

Listwise 결과는 신규 숏폼의 절대 성과 점수를 대체하지 않는다.

## 3. 데이터셋

### 현황

| 항목 | 수량 |
|---|---:|
| 채널 | 6 |
| 고유 롱폼 | 85 |
| 실제 공개 숏폼 | 94 |
| HIGH | 30 |
| MID | 34 |
| LOW | 30 |

채널은 BDNS, OOTB, 숏박스, 안원잘부, 워크맨, 피식대학이다.

### 정렬

```text
숏폼 첫·마지막 핵심 발화
  -> 롱폼 자막 후보 위치 검색
  -> 발화 순서·간격 기반 연속 구간 정렬
  -> Vpick scene/speech timestamp 대조
  -> start/end 확정
  -> mapping confidence 기록
```

Vpick 분석을 우선 사용하고 누락 시 `yt-dlp` 자막을 정렬 fallback으로
사용했다. 과도한 비연속 편집, 중복 Shorts ID, 정렬 불가 데이터는 교체하거나
제외했다.

### 정규화

채널별 기본 조회수 규모가 다르므로 채널 내 조회수 백분위를 상대 성과
정답으로 사용했다. 단, 백분위는 "그 채널 평소보다 잘됐는가"를 의미하므로
원조회수 순위도 보조 결과로 함께 보고한다.

MID 34개를 추가한 이유는 HIGH/LOW 극단만 사용할 때 라벨만 구분하는 가짜
판정자도 높은 pooled 상관을 얻는 shortcut을 확인했기 때문이다.

## 4. Pointwise 평가체계

### 입력

- 익명 후보 ID
- 후보 설명과 대사
- 생성 제목
- 실제 공개 Shorts 썸네일
- 필요 시 원본 개요와 전후 문맥

### 금지 입력

- 채널명과 URL
- 조회수와 좋아요
- HIGH/MID/LOW 또는 Pos/Neg
- 채널 백분위
- Gold 시작·종료 시각

### 최종 점수

```text
editorial_success_score
= (0.40 × 변화·반전
   + 0.15 × 제목 패키징
   + 0.45 × 썸네일 패키징) / 4
```

원본 내 중요도(salience)는 QVHighlights·TVSum의 개념을 반영한 진단값이지만,
현재 데이터에서 변화·반전 축과 중복되고 성과 정합성을 높이지 않아 최종
공식에는 포함하지 않았다.

### 성과 보정

```text
X = editorial_success_score
    + log1p(독립 채널 과거 Shorts 중앙 조회수)
    + log1p(게시 경과일)

y = log1p(실제 조회수)
model = Ridge regression
```

같은 롱폼의 후보가 학습과 평가에 동시에 들어가지 않도록 그룹 분할한다.
Ridge 규제 강도는 내부 fold에서 선택한다.

## 5. 선택 개선

### 후보군

- 단일 scene
- 인접 scene bridge
- 30·45·60·75초 window
- scene·speech boundary window

정확히 같은 구간을 제거한 뒤, 같은 scene 또는 약 55% 이상 겹치는 시간
변형을 동일 사건으로 묶고 대표 후보를 남긴다.

### Adaptive Coverage

롱폼을 5개 시간 구간으로 나눠 각 구간에서 Top1을 선택한다. 이 방식이
Judge-only보다 높은 Core@5를 기록했기 때문에 최종 방식의 구조 anchor로
사용한다.

### 혼합 보강

```text
AC Top4
+ highest-ranked eligible candidate(
    0.75 × structural prior
  + 0.25 × completion-gated Listwise Judge
  )
= final Top5
```

보강 후보는 AC Top4와 짧은 구간 기준 58%를 초과해 겹치면 제외한다.

## 6. 결과 해석

### 평가체계

- Pointwise 단독 원조회수 ρ: 0.212
- 성과 보정 후 전체 94 Group OOF ρ: 0.430
- Pointwise 순위 기반 후보 쌍 일치율: 64.4%

`40:15:45`는 현재 데이터에서 탐색한 최고식이다. 외부 일반화 성능이 아니다.

### 선택 개선

- Adaptive Coverage Core@5: 50.0%
- 최종 결합 Core@5: 55.6%
- Adaptive Coverage Best IoU@5: 0.361
- 최종 결합 Best IoU@5: 0.405

common18에서 기존 적중을 잃지 않고 한 건을 추가한 개발 결과다.

## 7. 레퍼런스 적용

- QVHighlights: 질의 조건부 구간 중요도와 saliency
- TVSum: 사람이 중요하게 느끼는 영상 요약 구간
- G-Eval: 근거 우선 평가 단계와 구조화 출력
- CheckEval: 복합 기준의 독립 체크 항목 분해
- NIST 평가 원칙: 개발·평가 분리, 재현성, 한계 명시

영상 원본을 안정적으로 입력하기 어려운 제약 때문에 레퍼런스 모델을 그대로
복제하지 않고 Vpick 텍스트·장면 증거로 관찰 가능한 기준만 변환했다.

## 8. 남은 검증

1. 동일 채널의 완전히 새로운 롱폼·숏폼 외부 Holdout 확대
2. 프롬프트·가중치·임계값을 고정한 단일 실행
3. 사람 2인 이상의 후보 선호·완결성 평가
4. 멀티모달 반복 안정성 개선
5. 충분한 데이터 확보 후 오픈소스 평가자 미세조정
