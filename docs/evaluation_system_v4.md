# Vpick 숏폼 평가체계 v4

## 1. 평가체계 정의

평가체계 v4는 이미 고정된 숏폼 후보 구간을 대상으로 `편집 구간 품질`과 `내재적 성과 잠재력`을 분리해 평가하고, LLM 판단의 반복 안정성·위치 편향·외부 성과 정합성·인간 판단 일치도를 검증하는 블라인드 시스템이다.

이 단계의 Judge는 새로운 구간을 선택하거나 타임스탬프를 수정하지 않는다. 후보 선택 Selector와 평가 Judge는 서로 다른 역할이다.

## 2. 평가 대상과 라벨

- 전체 Gold 롱폼-숏폼 페어: 45개
- Pos: 31개
- Neg: 9개
- Unlabeled: 5개
- 모든 구간의 `evaluation_role`: Gold
- `performance_label`: 채널 내 조회수 백분위에 따른 외부 성과 라벨

Pos와 Neg는 콘텐츠 품질의 절대 정답이 아니다. 동일 채널 안에서 상대적으로 조회 성과가 높거나 낮았다는 뜻이며, 제목·썸네일·업로드 시점·노출의 영향을 포함한다.

## 3. 블라인드 입력

LLM에는 다음 정보만 전달한다.

- 익명 후보 ID
- 구간 길이와 시작·종료 시각
- 언어와 장르
- Vpick 장면 설명
- 후보 내부 transcript
- 시작 전·종료 후 context

다음 정보는 private 파일에 격리하고 LLM에 전달하지 않는다.

- Pos/Neg 라벨
- 조회수와 좋아요
- 채널명
- Gold pair ID
- 게시된 Shorts ID와 주소

## 4. 판단 가능성

품질 점수 전에 각 후보의 근거를 1~5점으로 평가한다.

| 항목 | 의미 |
|---|---|
| description_support | 장면 설명이 사건·행동·반응을 구체적으로 보여주는 정도 |
| transcript_intelligibility | ASR 문법이 아니라 핵심 의미를 복원할 수 있는 정도 |
| boundary_observability | 시작과 끝의 완결성을 판단할 수 있는 정도 |
| visual_dependency | 화면·표정·자막·음향을 보지 않으면 핵심을 놓칠 가능성 |

근거가 부족하면 낮은 점수를 만들지 않고 `abstain`한다. ASR 오류는 콘텐츠 품질 감점 사유가 아니다.

## 5. 편집 구간 품질

`롱폼에서 숏폼 구간을 잘 잘랐는가`를 평가한다.

| 기준 | 가중치 |
|---|---:|
| 상황·논점 명확성 | 15% |
| 사건·대화·주장 진행성 | 15% |
| setup-payoff·결론 완결성 | 25% |
| 시작·종료 경계 자연스러움 | 20% |
| 의미 있는 콘텐츠 밀도 | 15% |
| 원본 없이 독립 이해 가능성 | 10% |

각 항목은 1~5점이며 코드는 0~100점으로 환산한다.

## 6. 내재적 성과 잠재력

제목·썸네일·노출 조건이 동일하다고 가정했을 때 `소재 자체가 시청과 공유를 유도할 가능성`을 평가한다.

| 기준 | 가중치 |
|---|---:|
| 감정·반응 강도 | 20% |
| 갈등·반전·발견·변화 | 20% |
| 소재의 구체성·새로움 | 20% |
| 공감·논쟁·공유 가능성 | 15% |
| payoff 강도 | 15% |
| 훅·제목화 가능성 | 10% |

성과 잠재력 점수는 실제 조회수 예측값이 아니다. 실제 Pos/Neg와의 정합성은 별도 보조 지표다.

## 7. 쌍대비교 설계

절대점수의 중앙 집중 문제를 줄이기 위해 같은 채널의 Pos와 Neg를 직접 비교한다.

- Pos와 Neg가 모두 있는 채널만 사용한다.
- Neg 9개 각각에 Pos 2개를 매칭해 총 18개 비교를 만든다.
- 같은 롱폼을 우선하고, 이후 같은 장르와 유사한 구간 길이를 우선한다.
- 좌우 배치는 해시 기반으로 무작위 결정한다.
- 2회차에는 좌우를 반대로 제시하고, 결과를 원래 방향으로 복원한다.
- 한 모델이 위치만 보고 판단하면 반복 일치도가 내려간다.

모델은 각 비교에서 다음을 반환한다.

- `editorial_preference`: left, right, tie
- `performance_preference`: left, right, tie
- 양쪽 후보의 세부 항목 점수
- evidence와 confidence
- score 또는 abstain
- 판단 근거

## 8. 검증 지표와 게이트

### 콘텐츠 Judge 검증

- 평가 커버리지 >= 0.80
- 좌우 반전 반복 일치도 >= 0.80
- 인간 평가 3명 x 18쌍 입력 완성률 = 1.00
- 인간 블라인드 평가 일치율 >= 0.70
- 인간 평가자 간 Fleiss' kappa >= 0.40

콘텐츠 Judge는 반복 신뢰도와 인간 일치도를 모두 통과해야 `validated_content_judge`가 된다.

### 외부 성과 정합성

- Pos 선호 정확도 >= 0.65
- 채널별 Pos 선호 정확도
- Pos/Neg 절대점수 차이와 AUC

외부 성과 정합성은 별도 진단이다. 이 기준을 실패했다고 인간이 선호하는 콘텐츠 Judge가 자동으로 무효가 되지는 않는다.

## 9. 인간 평가 프로토콜

세 명의 평가자가 서로 상의하지 않고 18개 비교를 블라인드 평가한다.

1. 각 후보의 지정된 시작·종료 구간만 확인한다.
2. `editorial_preference`에 더 잘 잘린 구간을 left, right, tie로 기록한다.
3. `performance_preference`에 동일 게시 조건에서 더 성과 잠재력이 높아 보이는 소재를 기록한다.
4. 판단할 근거가 부족하면 `insufficient_evidence=yes`로 기록한다.
5. confidence는 1~5로 기록한다.
6. 평가자는 조회수·좋아요·Pos/Neg 라벨을 보지 않는다.

인간 시트는 `results/gold_pairwise_judge_v4/input/human_pairwise_labels.csv`다. 54개 행은 18개 비교와 평가자 3명으로 구성된다.
한 행이라도 누락되거나 중복 평가자·잘못된 값이 있으면 최종 상태는 `pending_human_labels`로 유지된다. `insufficient_evidence=yes`는 낮은 품질이 아니라 `abstain` 판단으로 집계한다.
전체 실험을 재실행해도 비교 ID와 좌우 후보가 같은 행의 기존 사람 응답은 보존된다.

## 10. 현재 실험 결과

| 모델 | 커버리지 | 편집 반복 일치 | 성과 반복 일치 | Pos 선호 정확도 | 신뢰도 게이트 |
|---|---:|---:|---:|---:|---|
| GPT-5.6 Terra | 0.8889 | 0.8750 | 0.8750 | 0.4375 | 통과 |
| Claude Sonnet 5 | 1.0000 | 0.8235 | 0.7647 | 0.2778 | 실패 |

Terra는 인간 평가에 넘길 1차 Judge 후보이며 Claude는 보조 진단 모델이다. 두 모델 모두 외부 성과 정합성 기준은 통과하지 못했다. 특히 Pilot 채널에서 고성과 구간의 ASR와 장면 근거가 약했고, 저성과 구간이 텍스트상 더 완결된 사례가 확인됐다.

현재 상태는 `pending_human_labels`다. 이는 평가 코드가 미완성이라는 뜻이 아니라, 인간 검증 없이 Judge가 유효하다고 선언하지 않는 검증 규칙이 정상 작동하고 있다는 뜻이다.

## 11. 재현 명령

전체 쌍대비교를 다시 실행한다.

```bash
cd ~/vpick
REPEAT_COUNT=2 bash scripts/run_gold_pairwise_judge_v4.sh
```

인간 라벨을 작성한 뒤 API를 다시 호출하지 않고 최종 검증만 실행한다.

```bash
bash scripts/evaluate_gold_pairwise_humans.sh
```
