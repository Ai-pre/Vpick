# 단일 숏폼 성과 Judge v1 설계

## 1. 목표

새로 생성된 숏폼 후보 하나를 입력받아, 같은 채널에서 상대적으로 높은 성과를
낼 만한 신호가 있는지를 `0~100`으로 평가한다.

이 점수는 조회수 예측값이 아니다. 데이터셋이 채널별 성과 상위·하위 극단군으로
구성되어 있으므로, 출력은 다음 질문에 대한 상대 점수다.

> 이 후보가 지금까지 관찰한 채널 내 상위 성과군의 내용·구조 신호에 더 가까운가?

## 2. 정답 데이터

- 실제 유튜브 롱폼-숏폼 페어 60개
- Pos 30개, Neg 30개
- Pos/Neg는 같은 채널의 성과 백분위를 기준으로 정의
- 학습에는 실제 공개 숏폼만 사용
- 합성 후보와 pairwise 후보는 성과 정답으로 사용하지 않음

채널 백분위는 완벽한 품질 라벨이 아니다. 제목, 썸네일, 업로드 시점, 추천
알고리즘 같은 외생 변수가 섞여 있다. 이 데이터의 목적은 완벽한 정답을
주장하는 것이 아니라, 실제 성과와 연결된 신뢰 가능한 신호를 확보하는 것이다.

## 3. 입력

LLM에는 성과 정답을 숨긴 다음 정보만 전달한다.

- 후보 시작·종료 시각
- Vpick 장면 설명
- 장면·발화 타임스탬프
- 후보 내부 대사
- 시작·종료 경계를 보기 위한 짧은 전후 문맥
- Vpick 분석 실패 시 동일 형식으로 만든 `yt-dlp` 자막 기반 보강 장면

LLM에 전달하지 않는 정보:

- 채널명
- 조회수와 좋아요 수
- 채널 백분위
- Pos/Neg
- 실제 숏폼 URL과 제목

## 4. 두 단계 Judge

### 단계 A. LLM 특징 추출

LLM은 성과를 직접 맞히는 대신 후보에서 관찰 가능한 다음 항목을 독립적으로
채점한다.

- 원본 내 핵심성
- 초반 훅
- setup-payoff 회수
- 독립적 이해 가능성
- 정보·사건 밀도
- 시작·종료 경계 자연스러움

별도 Codex 평가에서는 반전, 감정 고점, 인용 가능성처럼 시장 반응과 관련된
세부 신호도 추출한다. 모든 점수는 아직 최종 성과 점수가 아니라 입력 특징이다.

### 단계 B. 성과 보정 모델

LLM 점수와 검증 가능한 자막·타임스탬프 구조 특징을 L2 정규화 로지스틱
모델에 입력한다. 이 모델만 Pos/Neg를 보며, 어떤 특징 조합이 실제 채널 내
성과 구분과 연결되는지를 학습한다.

구조 특징은 무조건 사용하지 않는다. 교차검증 성능을 개선한 경우에만 최종
모델에 포함한다.

## 5. 검증

주 검증은 `Leave-One-Longform-Out`이다. 같은 롱폼에서 나온 다른 숏폼이
학습과 검증에 동시에 들어가는 것을 막는다.

보고 지표:

- 전체 Pos/Neg AUC
- 채널별 AUC의 평균
- 채널 백분위와 점수의 Spearman 상관
- balanced accuracy
- 롱폼 단위 bootstrap 95% 신뢰구간

`Leave-One-Channel-Out`은 처음 보는 채널에서도 신호가 유지되는지 확인하는
스트레스 테스트다. 채널명은 입력 특징으로 사용하지 않는다.

## 6. Pairwise의 역할

Pairwise 평가는 다음 용도로만 사용한다.

- 같은 롱폼 후보끼리 어느 쪽이 더 좋은지 진단
- A/B 순서 편향 측정
- 경계 이동 후보와 hard negative 구분
- 후보 생성 파이프라인의 reranking

새 숏폼 하나의 성과 점수를 산출하는 배포 Judge는 pointwise 모델이다.
Pairwise 결과만으로 단독 후보의 절대 점수를 만들지 않는다.

## 7. 파인튜닝을 보류한 이유

현재 라벨은 60개뿐이고 채널 성과에는 콘텐츠 외 변수가 섞여 있다. 이 규모로
오픈소스 LLM 전체 또는 LoRA 파인튜닝을 하면 채널 말투, 등장인물, ASR 오류를
외우기 쉽다. 현재는 강한 API 모델을 고정된 특징 추출기로 사용하고, 작은
정규화 모델만 학습하는 편이 검증과 설명이 쉽다.

다음 조건을 만족하면 Qwen 계열 LoRA를 다시 검토한다.

- 실제 공개 숏폼 300~500개 이상
- 채널과 장르가 충분히 다양함
- 같은 롱폼 단위 train/validation/test 분리 가능
- 인간 평가 또는 반복 측정으로 라벨 노이즈를 추정함
- 현재 Opus/Codex 특징 기반 모델보다 독립 테스트셋에서 개선됨

## 8. 출력 해석

`high_performance_score_0_100`은 균형 잡힌 극단 표본 안에서의 고성과 신호다.
운영 환경의 실제 확률로 해석하지 않는다.

고성과·저성과 경계는 LOLO 예측에서 각 극단군 정밀도 75%를 목표로 정한다.
두 경계 사이의 후보는 억지로 Pos/Neg로 분류하지 않고 `uncertain`으로 남긴다.

## 9. 현재 한계

- 영상 프레임과 음향을 직접 보지 못하는 후보가 있음
- 제목·썸네일·업로드 시점·노출량을 사용하지 않음
- 60개 표본이라 신뢰구간이 넓음
- 같은 60개 교차검증으로 특징 조합도 선택하므로 보고 성능에 선택 편향이 남음
- 콘텐츠 품질이 좋아도 채널 내 하위 성과가 될 수 있음
- 점수는 후보 선택 보조 지표이며 성과를 보장하지 않음

현재 모델을 고정한 뒤 새로 수집하는 페어는 튜닝에 사용하지 않고 최종 테스트셋으로
보관해야 한다.

작업 맥락에서 완전히 분리된 API 호출이 아니므로 독립 검증 근거로 사용하지
않는다. 현재 입력만으로 채널 상대 성과를 예측하는 Judge가 검증됐다고 주장할
수 없다. 더 강한 LLM이나 파인튜닝보다 먼저 정답 정의와 입력 변수를 다시
설계해야 한다.
