# 다음 단계: Judge-first

## 결론

현재 메인 목표는 성과 분류기를 만들거나 Ours와 Vpick 후보를 비교하는 것이
아니다. 먼저 단일 숏폼 후보를 안정적이고 타당하게 채점하는 LLM-as-a-Judge를
검증해야 한다.

## 고정 순서

1. 평가 대상과 루브릭을 고정한다.
2. Gold 60개를 블라인드 pointwise 방식으로 2회 평가한다.
3. 반복 신뢰도를 검증한다.
4. 12개 인간 anchor와의 정합성을 검증한다.
5. engagement 점수만 채널 내부 Pos/Neg 성과 신호와 대조한다.
6. 새 잠금 테스트셋에서 재현한 뒤 Judge를 확정한다.
7. 그 뒤에만 Ours와 Vpick 개선 실험을 진행한다.

## 역할 분리

- `editorial_score`: 원본 내 핵심성, 독립적 이해, 전개·회수, 경계 완성도
- `engagement_score`: 초반 주목성, 변화·반전, 감정·정보 이득, 기억성
- `Pos/Neg`: engagement 축의 외부 타당도 검증용 채널 상대 성과 신호
- `human anchor`: Judge가 루브릭을 사람과 비슷하게 적용하는지 확인하는 보강 기준
- `Ours/Vpick`: Judge 검증을 통과한 뒤 수행하는 별도 개선 실험

Pos/Neg를 절대적인 좋은/나쁜 콘텐츠로 해석하지 않는다. 성과가 높은 채널의
Neg가 editorial 점수를 높게 받아도 모순이 아니다.

## 현재 상태

기존 v6, v8, Opus 4.8 실험은 반복 안정성 또는 성과 정합성 중 일부를
확인했지만 인간 타당도와 채널 내부 성과 타당도를 동시에 통과하지 못했다.
따라서 현재 검증된 Judge는 없다.

새 기준, 합격 게이트, 실행 파일은
`docs/llm_judge_first_protocol_v1.md`를 단일 기준 문서로 사용한다.
