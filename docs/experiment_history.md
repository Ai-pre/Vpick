# 실험 이력과 최종 채택 상태

이 문서는 결과가 좋은 실험만 남기지 않고, 각 시도가 최종 시스템에서 어떤
역할로 남았는지 기록한다.

| 실험 | 확인한 점 | 최종 상태 |
|---|---|---|
| 후보 설명만 Pointwise | 원본 중요도·경계 판단 부족 | 폐기 |
| 원본 문맥 포함 Pointwise | 반복성은 개선, 성과 정합성 약함 | 편집 진단 기반 |
| 직접 Pairwise | A/B 순서 편향, 신규 단독 후보 평가 불가 | 진단 전용 |
| 극단 Pos/Neg 60개 | pooled 상관 shortcut 발생 | MID 포함 94개로 대체 |
| Gemini 멀티모달 | HIGH 판별 개선, 반복 일관성 저하 | 보조 진단 |
| MR3-Qwen | 오픈소스 비교 가능성 확인 | 주 Judge 미채택 |
| Prometheus 파일럿 | 현재 입력·자원에서 이득 불명확 | 향후 재검토 |
| 원본 salience 추가 | 변화·반전과 중복, 성과식 개선 없음 | 진단값, 가중치 0 |
| Pointwise `50:25:25` | 사전 고정 비교 기준 | 공식 baseline |
| Pointwise `40:15:45` | 현재 94개에서 최고 성과 정합성 | 개발 선택식 |
| 성과 보정기 | 콘텐츠 점수와 채널·게시 조건 분리 | 채택 |
| Judge-only Top5 | common18 Core@5 22.2% | 폐기 |
| Adaptive Coverage | common18 Core@5 50.0% | 구조 baseline |
| AC Top4 + 혼합 후보 | Core@5 55.6%, 기존 hit 유지 | 최종 개발 방식 |

## 주요 의사결정

### 높은 pooled 상관을 그대로 채택하지 않음

HIGH는 높게, LOW는 낮게, MID는 무작위로 주는 가짜 판정자가 높은 pooled
상관을 얻는 것을 확인했다. 이후 연속 백분위, 같은 채널 쌍 순서, 그룹 분할,
원조회수 결과를 함께 보고하도록 변경했다.

### Pairwise를 운영 Judge로 사용하지 않음

Pairwise는 후보 두 개가 함께 있어야 하고 제시 순서에 영향을 받을 수 있다.
신규 후보 하나의 점수를 출력해야 하는 운영 요구에는 Pointwise가 적합하다.
Pairwise는 반복·순서 편향 진단에만 남겼다.

### Judge가 구조 선택기를 완전히 대체하지 않음

Judge-only Top5가 Adaptive Coverage보다 낮았다. 따라서 시간대 분산과 후보
탐색은 구조 선택기가 담당하고, Judge는 완결된 비중복 후보 하나를 보강한다.

### 멀티모달을 핵심 입력에서 제외

소규모 파일럿에서 결정적 HIGH 판별은 개선됐지만 동일 입력 반복 판단이
불안정했다. 영상 다운로드·권한·비용 제약도 있어 핵심 Judge가 아닌 향후
보조 신호로 남겼다.

## 해석 규칙

- `selected`: 현재 개발 시스템에서 사용
- `baseline`: 비교를 위해 고정
- `diagnostic`: 결과 해석과 실패 원인 확인용
- `rejected`: 최종 출력에 사용하지 않음
- `requires_external_holdout`: 외부 일반화 주장을 보류
