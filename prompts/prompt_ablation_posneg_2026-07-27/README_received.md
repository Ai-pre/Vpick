# 프롬프트 5종 — 설계 의도와 실행 방법

각 버전은 무작위 변주가 아니라 **하나의 가설**을 검증합니다.
어느 것이 이겼는지보다, **왜 이겼는지**를 알 수 있게 축을 하나씩만 움직였습니다.

## 버전별 가설

| 버전 | 바꾼 것 | 검증하려는 가설 |
|---|---|---|
| **V1** `baseline` | 없음 (현재 프롬프트 그대로) | 기준선. 나머지가 이걸 이겨야 의미가 있음 |
| **V2** `resolution` | 1~5 → 0~100, 체크리스트 0/1/2 → 0~4, "확신 없으면 3점" 제거, 분포 제약 제거 | **동점만 없애도 변별력이 오른다** |
| **V3** `evidence_first` | V2 + 관찰 서술과 원문 인용을 점수보다 먼저 출력 | **사후 정당화를 막으면 점수가 근거에 묶인다** |
| **V4** `direct_percentile` | 체크리스트 전부 제거. "이 채널 숏폼 중 상위 몇 퍼센타일?"만 직접 예측 | **분해 채점의 중간 항목이 오히려 노이즈다** |
| **V5** `funnel` | 시청 행동 3단계 확률(멈춤/완주/공유)을 각각 예측, 곱으로 집계 | **추상적 "시장성"보다 구체적 행동 확률이 잘 보정된다** |

### 왜 이 5개인가

- **V2**는 진단된 가장 큰 문제(동점)를 정면으로 겨냥합니다. V1 대비 개선이 없다면 척도 문제가 아니라는 뜻입니다.
- **V3**는 V2에서 딱 한 축(추론 순서)만 더 움직입니다. V3 > V2면 그 차이는 순서 때문입니다.
- **V4**는 정답 기준(`channel_performance_percentile`)과 **같은 척도로 직접 물어봅니다.** 정답이 채널 내 백분위인데 judge에게는 추상적 "시장성"을 묻는 현재 구조가 불필요한 변환을 끼워넣고 있을 수 있습니다.
- **V5**는 유일하게 산식이 곱셈이라 **해상도가 공짜로 확보됩니다.** 세 값의 곱은 좀처럼 충돌하지 않습니다.

### 모든 버전에 공통으로 적용한 수정

원래 프롬프트에서 진단된 문제 중, **가설과 무관한 것들**은 V2~V5에 일괄 반영했습니다.
(이것들까지 버전마다 다르면 무엇 때문에 이겼는지 알 수 없습니다.)

- `description_support` 항목 제거 — 입력에 시각 정보가 거의 없어 채워질 수 없는 항목
- `visual_dependent` 플래그 제거 — 전 후보가 동일 조건이라 항상 켜지거나 항상 꺼짐
- 분포 제약("5점은 10% 이내") 제거 — 독립 채점과 논리적으로 모순
- "확신이 없으면 중앙값" 문구 제거 — 변별이 목적인 과제와 정반대
- evidence 점수는 순위 산식에서 제외 (기록은 유지)

## 실행

```bash
# 1) 각 프롬프트로 채점 -> out_V1.jsonl ... out_V5.jsonl
#    반복 3회 권장 (자기일관성 측정용)

# 2) 해상도 먼저 확인하고 집계식 확정
python aggregate_judge_output.py out_V4.jsonl --compare

# 3) 공통 점수로 변환 (스키마 자동 감지)
python aggregate_judge_output.py out_V4.jsonl --run 1 --out js_V4_r1.csv

# 4) 평가
python evaluate_judge.py js_V4_r1.csv --outdir res_V4
```

반복 3회를 한 파일에 합칠 때는 `run` 컬럼(1,2,3)을 넣으면
`evaluate_judge.py`가 회차 평균을 쓰고 자기일관성까지 계산합니다.

## 읽는 법

**전체 Spearman은 보지 마십시오.** pos/neg가 완전히 분리된 데이터셋이라
아무 judge나 0.7~0.8이 나옵니다. 실제로 pos/neg만 구분하고 그룹 내부는 무작위인
가짜 judge가 전체 ρ 0.730을 기록했습니다.

봐야 할 것은 이 순서입니다.

1. **셀(채널×라벨) 내부 일치율** — 50%면 동전 던지기, 65%↑ 쓸 만함, 75%↑ 좋음
2. **자기일관성** — 반복 간 상관. 이 값보다 성능이 높으면 그 성능은 우연입니다
3. **고유 점수 개수 / 최대 동점 덩어리** — 20 이상 / 5 이하
4. **abstain 비율** — 입력 충실도와 얽혀 있으므로 버전 간 비교 시 반드시 함께 보십시오

## 스크리닝 요령

60개를 다 돌리기 전에 **같은 롱폼에서 나온 pos/neg 쌍 4건**을 먼저 넣어보십시오.

| 롱폼 | pos | neg |
|---|---|---|
| `bvUS-ri9nqQ` | P001 (807~903s, 935만) | N026 (750~809s, 52만) |
| `heifaIjlSUc` | P007 (619~664s, 693만) | P008 (355~397s, 60만) |

같은 영상·같은 채널·같은 출연자이고 **구간 선택만 다릅니다.**
여기서 순서가 안 맞으면 60개에서도 안 됩니다. 호출 4번으로 후보를 걸러낼 수 있습니다.
